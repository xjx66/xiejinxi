# 一期 Demo 方案：手动上传的 AI 世界编辑器

## 1. 文档定位

本文档是在 [ai-world-interaction-system-notes.md](file:///Users/bytedance/Desktop/our-website/docs/product/ai-world-interaction-system-notes.md) 的最终产品方向基础上，收敛出的第一期 Demo 方案。

目标不是一次性实现完整的 AI 世界编辑器，而是先做出一个能够被真实演示、真实使用、真实验证的最小闭环。

本期只做：

- 世界坐标中的手动创建与摆放
- 用户手动上传现有支持的对象素材
- 对象的基础管理、选中、移动、替换、删除
- 世界保存与恢复

<br />

第一期 Demo 是一个“手动上传版的空间对象编辑器”，而不是完整的 AI 世界编辑器。

## 1.1 当前实现进度

当前仓库已经落下第一版“模拟 AI 交互”入口：

- 右侧固定全局 AI 面板已替换原角色对话面板
- 用户可先锁定坐标或选中对象，再上传资产并提交
- 当前使用代码规则模拟 AI 决策，不接真实模型
- 已支持图片、视频、GLB 三类资产
- 已支持：
  - 空白坐标创建对象
  - 现有对象跨类型替换

当前仍未完成：

- 世界持久化保存 / 恢复
- 完整对象属性编辑表单
- 系统素材库面板
- avatar 直接替换

## 2. 一期目标

## 2.1 业务目标

通过一期 Demo，先验证三件事：

- 用户是否能理解“在 3D 世界里编辑对象”这件事
- 当前场景架构是否能承载“世界对象数据化”
- 上传素材 -> 放入世界 -> 调整 -> 保存，这条路径是否顺畅

## 2.2 演示目标

一期 Demo 至少要能让人完成下面这个完整流程：

1. 打开世界
2. 点击一个位置获得世界坐标
3. 选择要创建的对象类型
4. 上传一个本地素材或选择一个已有素材
5. 在该坐标创建对象
6. 选中对象后调整位置、缩放、朝向
7. 保存世界
8. 下次进入时恢复同样的布局

如果这条链路顺畅，就证明“世界编辑器”这个方向成立。

## 3. 用户与场景

## 3.1 目标用户

一期面向两类用户：

- 内部演示用户：用于验证产品方向、给投资人或合作方看 Demo
- 早期创作者：愿意自己上传图片、视频、模型，在空间中布置内容的人

## 3.2 核心使用场景

建议聚焦 3 个场景：

- 展示空间：上传图片、视频、模型，做一个空间展厅
- 品牌空间：手动摆放产品模型、海报、视频介绍屏
- 个人世界：把自己的素材手动布置成一个可漫游的空间

## 4. 一期范围

## 4.1 必做能力

- 世界坐标显示
- 点击地面获取坐标
- 统一对象创建入口
- 手动上传素材
- 已有素材复用
- 对象在世界中的实例化
- 对象选中与高亮
- 对象基础属性编辑
- 对象删除
- 世界保存 / 加载

## 4.2 可延后能力

- 拖拽上传
- 批量上传
- 撤销 / 重做
- 分组
- 图层
- 材质细调
- 对象级版本历史

## 4.3 明确不做

- AI 文本生成 3D 对象
- AI 改材质、改造型、改布局
- 智能推荐放置位置
- 自动施工态动画流水线

一期里如果需要“施工态”，只做一个非常轻量的上传中 / 处理中占位态即可。

## 5. 对象类型设计

一期只支持当前项目里已经天然存在、且容易落地的对象类型。

## 5.1 支持的对象类型

- `model`
- `image`
- `video`
- `avatar-template`

## 5.2 与当前项目的对应关系

- `model`
  - 对应当前 `products` 中使用的 `glb`
  - 也可承接树、雕塑、产品、装置等 3D 物体
- `image`
  - 对应当前 `paintings`
  - 用户上传图片后，以画框 / 展板 / 悬浮展示牌方式呈现
- `video`
  - 对应当前 `products` 中的视频屏
  - 用户上传视频后，以屏幕、立面面板或展墙形式呈现
- `avatar-template`
  - 暂不支持用户上传自定义角色
  - 只允许从现有角色模板库中手动添加

## 5.3 一期暂不支持的类型

- `text`
- `light`
- `environment`
- `procedural`

这些类型会拉大系统复杂度，不适合一期。

## 6. 一期核心交互闭环

## 6.1 创建对象

建议的最小路径如下：

1. 用户在 3D 世界中点击一个位置
2. 系统记录该点的世界坐标
3. 右侧打开“创建对象面板”
4. 用户选择对象类型：模型 / 图片 / 视频 / 角色模板
5. 用户上传本地文件，或从现有资产库中选择
6. 点击“确定创建”
7. 系统在该位置生成对象实例

## 6.2 编辑对象

用户点击选中对象后，右侧展示“对象属性面板”，支持以下基础编辑：

- 名称
- 位置 `position`
- 朝向 `rotation`
- 缩放 `scale`
- 素材替换
- 显示状态
- 删除对象

一期不做复杂 gizmo，优先用表单 + 步进按钮的方式完成编辑。

## 6.3 保存世界

右上角提供一个明确的“保存世界”按钮。

保存内容包括：

- 世界对象列表
- 每个对象的类型
- 每个对象的坐标、旋转、缩放
- 素材引用
- 基础元数据

加载页面时恢复这些对象。

## 7. 产品界面建议

一期建议采用“三段式编辑界面”：

## 7.1 中间主视区

- 第一人称 3D 世界
- 保留现有相机和移动方式
- 保留当前统一选中高亮能力
- 显示当前相机坐标和点击点坐标

## 7.2 左侧资源区

左侧作为资源面板，分为两类：

- 我的上传
- 系统素材

系统素材可预置：

- 当前已有 `glb`
- 当前已有画作图片
- 当前已有视频素材
- 当前已有角色模板

## 7.3 右侧属性区

右侧属性区根据状态切换：

- 未选中任何对象时：显示“创建对象”
- 选中对象后：显示“对象属性编辑”

这样最符合一期 Demo 的低学习成本原则。

## 8. 上传能力方案

## 8.1 一期允许的上传格式

- 模型：`.glb`
- 图片：`.png` `.jpg` `.jpeg` `.webp`
- 视频：`.mp4`

## 8.2 上传后的处理逻辑

一期不做复杂转码流水线，只做轻量规范：

- 图片上传后直接生成 `image` 资产记录
- 视频上传后直接生成 `video` 资产记录
- `glb` 上传后直接生成 `model` 资产记录

如果文件格式不符合要求，则直接拒绝并提示。

## 8.3 资产来源

一期资产来源分两种：

- `system`
  - 仓库中已有的预置资源
- `user-upload`
  - 用户手动上传的资源

这样后续很容易扩展到真正的资产管理系统。

## 9. 数据结构建议

一期虽然不做完整后端平台，也应该从一开始按“世界数据”思路来设计。

## 9.1 World

```json

  "id": "world_demo_001",
  "name": "Demo World",
  "theme": "dark",
  "version": 1
}
```

## 9.2 WorldObject

```json
{
  "id": "obj_001",
  "type": "model",
  "assetId": "asset_001",
  "position": { "x": 120, "y": -5, "z": -150 },
  "rotation": { "x": 0, "y": 1.57, "z": 0 },
  "scale": { "x": 1, "y": 1, "z": 1 },

  "metadata": {
    "title": "My Uploaded Model",
    "source": "user-upload"
  }

```

## 9.3 Asset

```json
{
  "id": "asset_001",
  "kind": "glb",
  "source": "user-upload",
  "name": "pavilion.glb",
  "url": "/uploads/pavilion.glb",
  "previewUrl": "/uploads/previews/pavilion.png"
}
```

## 9.4 一期存储方式建议

一期可以先从低成本方案开始：

- 世界配置：`localStorage` 或本地 JSON
- 上传素材：先落本地静态目录或简单文件存储
- 系统素材：直接来自仓库已有 `assets`

如果后面要做线上演示，再替换为：

- 世界数据接口
- 资产上传接口
- 对象保存接口

## 10. 前端架构建议

## 10.1 保留的现有能力

当前项目已经可直接复用：

- 世界坐标系
- 点击点坐标回显
- 第一人称漫游
- 统一选中系统
- 各类对象统一命中逻辑
- 标签与加载态基础能力

## 10.2 一期新增模块

建议新增 5 个模块：

- `world-state.js`
  - 管理世界对象列表、保存、加载
- `asset-library-runtime.js`
  - 管理系统素材与用户上传素材
- `object-factory.js`
  - 根据对象类型实例化 `model/image/video/avatar-template`
- `editor-panel.js`
  - 管理创建面板与属性面板
- `upload-runtime.js`
  - 管理上传、校验、预览、资产落库

## 10.3 为什么这样拆

这样拆的好处是：

- 不需要一开始就重写整个场景
- 能逐步把硬编码内容迁移成“世界对象数据驱动”
- 为二期 AI 创建 / AI 编辑留接口

## 11. 一期对象表现方案

## 11.1 model

- 使用 `GLTFLoader`
- 加入统一碰撞体与选中系统
- 支持位置、旋转、缩放

## 11.2 image

- 统一渲染为展板或画框对象
- 仍然走标准世界对象逻辑
- 支持替换图片

## 11.3 video

- 统一渲染为视频屏对象
- 支持播放 / 暂停
- 支持替换视频

## 11.4 avatar-template

- 从现有角色模板库中选择
- 作为标准世界对象加入场景
- 保留当前角色基础交互

## 12. 一期状态机建议

虽然不做 AI 施工态，但上传与创建仍建议保留一个最简状态机：

- `draft`
- `uploading`
- `processing`
- `ready`
- `failed`

对应体验：

- `draft`
  - 用户刚选择类型和素材，但尚未提交
- `uploading`
  - 文件上传中
- `processing`
  - 创建对象中，场景里可显示轻量占位框
- `ready`
  - 对象可正常选中与编辑
- `failed`
  - 失败提示并支持重试

## 13. 一期成功标准

一期 Demo 成功，不是因为功能很多，而是因为下面这些关键动作都稳定：

- 点击世界坐标创建对象
- 上传文件并成功创建对象
- 不同对象都能被稳定选中
- 属性编辑后场景即时更新
- 保存后再次进入可以恢复

如果以上能力稳定，一期就已经足够支撑产品 Demo。

## 15. 二期预埋接口

虽然一期不做 AI 编辑，但接口设计上应提前留位：

- `createObjectFromAsset()`
- `updateWorldObjectPatch()`
- `replaceWorldObjectAsset()`
- `saveWorldSnapshot()`
- `loadWorldSnapshot()`

后续二期只需要把 AI 输出转成这些结构化调用，而不是重写整个编辑器。

## 16. 建议的下一步

如果要继续推进，我建议立刻进入下面三个动作：

1. 先把一期对象类型和上传格式定死
2. 再把 `WorldObject` 和 `Asset` 的最小 schema 定死
3. 然后开始从当前 `talkinghead.js` 中拆出 `world-state` 与 `object-factory`

这样能最快从“概念讨论”进入“可运行的一期 Demo 实现”。
